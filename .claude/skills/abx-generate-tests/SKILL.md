# abx test suites

Every experiment is only as good as its suite: candidates are scored 0–10 by an LLM judge against each test case's `rubric`. Spend effort here.

## Format

```json
{
  "task_description": "Extract calendar dates from text",
  "evaluation_model": "haiku",
  "test_cases": [
    {"input": "The meeting is on March 5, 2024 at 3pm.",
     "rubric": "Must extract the full date including year; 10 = ISO date + time, 5 = date without year, 0 = no date"}
  ]
}
```

- `input` is appended to the candidate's user prompt as `"\n\nInput: <input>"` (`abx/evaluator.py`). Placeholders like `{input}` in a user prompt are **not** substituted.
- `expected_score` (0–10) is only used by self-optimization; see the `abx-self-improve` skill.

## Option A: generate from existing prompts

```bash
abx generate-tests \
  --task "Extract calendar dates from text" \
  --system-prompt prompts/system.txt \
  --user-prompt  "Extract all dates from the text below." \
  --count 8 \
  --output tests.json
```

- `--system-prompt` / `--user-prompt` take inline text **or** a file path (a path that exists is read). At least one must be non-empty.
- `--count` is 1–20 (default 5). `--provider` is `claude` (default) or `deepseek`; `--model` defaults to the provider's default (`haiku` / `deepseek-v4-flash`).
- This is one billed LLM call: charged to the user's Claude account with `--provider claude`, or needs `DEEPSEEK_API_KEY` with `--provider deepseek`.

## Option B: write it by hand

Prefer this when the user can describe real inputs, or combine: generate, then edit.

## Review before using (always do this)

Read the resulting file and check, then tell the user what you changed:
1. **Rubrics are gradeable.** Each says what earns 10, ~5 and 0, not just "should be good".
2. **Coverage.** Easy, typical, edge and adversarial inputs; no near-duplicates.
3. **Size.** 8–15 cases is a reasonable balance. Each case costs 2 LLM calls per candidate per generation, so cases × population × (cycles+1) × 2 is the call count of a run.
4. **No leakage.** The rubric is never shown to the candidate, so it must not depend on hidden context the prompt can't know.

Next step: `abx init --task "..." --tests tests.json` (see `abx-run-experiment`).
